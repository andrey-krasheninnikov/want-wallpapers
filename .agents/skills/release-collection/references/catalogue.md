# Подготовка каталога коллекции

## CDN

Поддерживается публичный HTTPS URL с host `want-foundation.s3.twcstorage.ru`, bucket `want-foundation` и папкой `wallpapers/assets/collections/<number-and-name>/`. Не используйте URL с credentials, другой bucket или host с текущим `s3Url`. Из другого адреса нельзя молча вывести адрес текущего CDN.

Получите S3 ListObjectsV2 через `https://want-foundation.s3.twcstorage.ru/?list-type=2&prefix=<encoded-folder-prefix>`, где prefix начинается с `wallpapers/assets/collections/`. Разберите XML стандартной библиотекой; проходите страницы через `NextContinuationToken` до `IsTruncated=false`. Ограничьте список точным prefix коллекции. Пропустите маркеры папок и вспомогательные файлы; ни один PNG не должен остаться без разбора.

Папка задаёт `collection.id` с ведущими нулями и `collection.slug` без цифрового префикса. Для каждого положительного уникального номера ожидаются ровно `<number>-desktop.png` и `<number>-mobile.png`. Нумерация может иметь пропуски. Нестандартное имя, дубликат варианта или неполная пара требуют выяснения; не пропускайте такой дизайн. `count` — число пар, а не файлов.

Скачайте PNG в временную папку вне Git. Проверьте HTTP-статус, тип `image/png`, декодирование и размеры через установленный `sharp`: обе стороны не меньше 500 px, как в `sync-previews.ts`. Просмотрите оба варианта, чтобы тексты описывали реальное изображение. Сохраните список объектов и ETag/хеши; перед публикацией повторно проверьте исходники. При изменении списка или содержимого повторите подготовку кандидата и проверки.

## Manifest

Сохраните публичные метаданные как JSON вне секретов и build output:

```text
{
  collection: { id, slug, count, title, description },
  wallpapers: [
    { id, slug, collection, collectionId, s3Folder, fileStem,
      number, category, tags, title, description }
  ]
}
```

Используйте реальные JSON ключи и значения. Все `title` и `description` содержат непустой текст для `en`, `ru`, `zh-cn`, `pt-br`. Для обоев `id` и `slug` равны `<collection.slug>-<number>`, `collection` и `fileStem` — slug коллекции, `collectionId` и `s3Folder` — полный ID папки. Не меняйте эти связи: они сохраняют публичные URL и связь с рейтингами/комментариями. `fileStem` сохраняется в manifest для совместимости; на текущем CDN имя файла состоит только из number и варианта.

Пишите конкретные названия и описания по композиции, цвету, материалам и объектам. Тон Want: ясно, лично, без рекламных обещаний и набивки ключевыми словами. Сохраняйте смысл во всех четырёх языках. Категории и теги используйте из `categoryLabels`/`tagLabels`; новые ключи требуют четырёх переводов в frontend, обновления backend taxonomy и отдельного разрешённого деплоя до рабочего импорта. SEO-поля и поисковый индекс строятся из этих метаданных автоматически.

## Сюжет коллекции

Подготовьте отдельную атмосферную историю для коллекции на `en`, `ru`, `zh-cn`, `pt-br`. Опирайтесь на просмотренные изображения: место, предметы, цвет, освещение и движение. В художественном сюжете допустимы вымышленные действия и детали. Не выдавайте их за описание того, что изображено на каждом PNG. Названия, короткие описания, alt, категории и теги остаются фактическими метаданными.

Текст рассказывает, что происходит, без выводов, морали, авторских оценок и рекламных обещаний. Вместо очевидных инструкций по скачиванию и установке создавайте сцену с конкретными действиями и деталями. Не объясняйте читателю смысл истории и не добавляйте итоговый тезис. Ориентир для каждой версии: около 200–300 слов; для китайского используйте естественные предложения и отдельно проверьте сегментацию через существующую `wordCount` с `Intl.Segmenter`.

Прочитайте и примените `$humanizer:humanizer`: проверьте целый текст, отредактируйте ритм и повторяющиеся конструкции, сохраните сюжет и смысл локализаций. В репозиторий записывайте только окончательный текст. Прочитайте каждую версию целиком: в ней не должно быть искусственных противопоставлений, шаблонных троек, повторяющихся эффектных концовок и навязанных интерпретаций.

Храните историю в `collectionStories` в `frontend/src/data/editorial.ts` по стабильному slug коллекции, отдельно от перезаписываемого `catalog-live.json` и импортируемого manifest. Заполните все четыре локали. Общий компонент `Editorial.astro` показывает историю на странице коллекции и её обоев ниже основных изображений; на главной и в списке коллекций показывает начало истории со ссылкой на коллекцию. Реальные размеры и формат PNG, а также действующую лицензию выводите отдельно от художественного текста. Не подменяйте лицензирование или размеры вымышленными сведениями.

После `catalog:pull` подтвердите сохранность истории. В сборке проверьте её наличие на новой странице коллекции и страницах обоев во всех локалях, а также локальные метрики видимого текста и HTML. Метрики не подтверждают устранение предупреждений внешнего аудита. В браузере проверьте длинный текст на узком экране, ссылки и доступность; новые истории не должны перекрывать просмотр и скачивание.

Выполните `bun run catalog:add /absolute/path/collection.json --dry-run`. Эта проверка не читает CDN и Rust API; доступность и пары PNG проверяются отдельно. После успешной подготовки выполните рабочий импорт по README, затем `catalog:pull`, сборку и UI-проверки. Не добавляйте PNG/WebP, `.env`, токен или `dist/` в коммит.

Рабочий импорт использует `BACKEND_API_URL=https://wallpapers.want.foundation` и внешний `CATALOG_API_TOKEN_FILE`. URL должен быть HTTPS origin; HTTP разрешён только для localhost/127.0.0.1. Токен разрешает только операции каталога. Импорт атомарен: точный повтор возвращает no-op, частичные или отличающиеся записи дают conflict без записи. После неоднозначного ответа сначала выполните API readback. Firebase используется только для Analytics.
