# Подготовка каталога коллекции

## CDN

Поддерживается публичный HTTPS URL с host `s3.twcstorage.ru`, bucket `wallpapers` и папкой `assets/collections/<number-and-name>/`. Не используйте URL с credentials, другой bucket или host с текущим `s3Url`. Из другого адреса нельзя молча вывести адрес текущего CDN.

Получите S3 ListObjectsV2 через `https://s3.twcstorage.ru/wallpapers?list-type=2&prefix=<encoded-folder-prefix>`. Разберите XML стандартной библиотекой; проходите страницы через `NextContinuationToken` до `IsTruncated=false`. Ограничьте список точным prefix коллекции. Пропустите маркеры папок и вспомогательные файлы; ни один PNG не должен остаться без разбора.

Папка задаёт `collection.id` с ведущими нулями и `collection.slug` без цифрового префикса. Для каждого положительного уникального номера ожидаются ровно `<slug>-<number>-desktop.png` и `<slug>-<number>-mobile.png`. Нумерация может иметь пропуски. Нестандартное имя, дубликат варианта или неполная пара требуют выяснения; не пропускайте такой дизайн. `count` — число пар, а не файлов.

Скачайте PNG в временную папку вне Git. Проверьте HTTP-статус, тип `image/png`, декодирование и размеры через установленный `sharp`: обе стороны не меньше 500 px, как в `sync-previews.ts`. Просмотрите оба варианта, чтобы тексты описывали реальное изображение. Сохраните список объектов и ETag/хеши; перед публикацией повторно проверьте исходники. При изменении списка или содержимого повторите подготовку кандидата и проверки.

## Manifest

Сохраните публичные метаданные как JSON вне секретов и build output:

```text
{
  collection: { id, slug, count, title, description },
  wallpapers: [
    { id, slug, collection, collectionId, s3Folder, fileStem,
      number, category, tags, title, description }
  ]
}
```

Используйте реальные JSON ключи и значения. Все `title` и `description` содержат непустой текст для `en`, `ru`, `zh-cn`, `pt-br`. Для обоев `id` и `slug` равны `<collection.slug>-<number>`, `collection` и `fileStem` — slug коллекции, `collectionId` и `s3Folder` — полный ID папки. Не меняйте эти связи: они задают URL, варианты и связь с рейтингами/комментариями.

Пишите конкретные названия и описания по композиции, цвету, материалам и объектам. Тон Want: ясно, лично, без рекламных обещаний и набивки ключевыми словами. Сохраняйте смысл во всех четырёх языках. Категории и теги используйте из `categoryLabels`/`tagLabels`; добавляйте новые ключи с четырьмя переводами только при необходимости. SEO-поля и поисковый индекс строятся из этих метаданных автоматически.

Выполните `bun run catalog:add /absolute/path/collection.json --dry-run`. Эта проверка не читает CDN и Firebase; доступность и пары PNG проверяются отдельно. После успешной подготовки выполните рабочий импорт по README, затем `catalog:pull`, сборку и UI-проверки. Не добавляйте PNG/WebP, `.env`, сервисный ключ или `dist/` в коммит.

Рабочий импорт использует только `want-wallpapers`; при `FIRESTORE_EMULATOR_HOST=127.0.0.1:<port>` используется только `demo-want-wallpapers`. Для автоматической записи в рабочий каталог нужны права сервисного аккаунта на данные Firestore. Firebase CLI login сам по себе не предоставляет Admin SDK этот доступ. Тариф остаётся Spark.
