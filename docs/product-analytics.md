# Продуктовая аналитика

Публичный сайт использует существующий Firebase Analytics и поток GA4 `G-T8PQT8GE9B`. Аналитика помогает сравнивать коллекции и источники переходов, находить потери перед скачиванием и проверять использование функций. Админка и development kit исключены. Rust API и PostgreSQL не отправляют продуктовые события в Google.

## Что считаем

`wallpaper_download` означает запуск нативного PNG-скачивания. Событие не подтверждает сохранение файла на устройство. Нажатие кнопки, открытие рекламного диалога и запуск PNG считаются разными действиями. Существующее имя события сохраняется.

`telegram_click` означает переход по предусмотренной сайтом Telegram-ссылке. `destination` различает `channel`, `author`, `foundation` и `emoji`. Переход не подтверждает подписку на канал или добавление emoji pack.

Показ карточки учитывается после непрерывной секунды с видимостью не менее 50% в активной вкладке. Одна карточка в неизменном наборе результатов повторно не учитывается. Быстрый клик может произойти до подтверждения показа; CTR не ограничивается искусственно. Для раздела наблюдается заголовок, поэтому длинный раздел не обязан целиком помещаться на экране.

## Согласие и данные

Сохраняется модель ADR 0005: явный выбор имеет приоритет; вне ЕЭЗ defaults разрешают аналитику после определения страны, а ЕЭЗ и неизвестная страна требуют выбора. Реклама имеет отдельное разрешение. Отказ и отзыв не мешают просмотру, поиску, социальным действиям и нативным скачиваниям.

До разрешения Firebase Analytics не запускается, продуктовые действия не сохраняются для последующей отправки. Во время загрузки SDK после разрешения очередь хранит максимум 50 событий до 30 секунд только в памяти. Отправка начинается после готовности SDK. Отзыв очищает очередь и отключает дальнейший сбор, включая другую вкладку и незавершённую загрузку.

Параметры содержат публичные идентификаторы каталога, язык, вариант, место действия и ограниченные числовые значения. Свободный поиск заменяется распознанными терминами каталога. Для распознавания используются первые 500 символов; передаются максимум три целых идентификатора общей длиной до 100 символов. Тексты форм, email, комментарии, внутренние visitor ID, сырые ошибки, query и fragment не передаются. Внешний referrer сокращается до origin. Google Signals, персонализация и собственный User-ID не используются. Стандартные идентификаторы SDK остаются под разрешением аналитики.

GA4 описывает аудиторию с разрешённой и доступной аналитикой. Посетителей без JavaScript, с отказом или блокировщиком не пытаемся учитывать обходным способом.

## События

Все события включают `locale`, `page_type`, очищенные `page_location`, `page_referrer` и служебный `page_title`, равный типу страницы. На странице работы также передаются `item_id`, `collection_id` и `category`. Реальные названия, описания и произвольные тексты в этих параметрах не используются.

| Событие | Момент отправки | Параметры действия |
| --- | --- | --- |
| `page_view` | Открытие публичной страницы, включая переход Astro | Общий контекст |
| `navigation_click` | Внутренняя ссылка | `target_page`, `placement` |
| `card_view` | Подтверждённая видимость карточки | `content_type`, `item_id`, `collection_id`, `category`, `placement`, `position` |
| `content_select` | Переход из карточки | Те же поля карточки |
| `wallpaper_view` | Открытие работы | `item_id` и общий контекст |
| `download_click` | Нажатие основной кнопки | `item_id`, `variant` |
| `wallpaper_download` | Запуск нативного PNG | `wallpaper`, `variant` и общий контекст |
| `variant_change` | Явный выбор desktop/mobile | `item_id`, `variant` |
| `wallpaper_navigate` | Навигация к соседней работе | `direction`, `method` |
| `catalog_search` | 500 мс без изменения поиска/фильтров | `result_count`, `query_length`, распознанные `search_terms` |
| `filter_change` | Выбор категории или коллекции | `filter_type`, `filter_id` |
| `search_reset` | Сброс поиска/фильтров | Общий контекст |
| `rating_action` | Попытка, подтверждение API или ошибка | `item_id`, `stage`, `rating`, `error_code` |
| `comment_action` | Отправка, удаление или жалоба | `item_id`, `action`, `stage`, `error_code` |
| `feedback_action` | Открытие, начало заполнения, попытка, результат | `stage`, `error_code` |
| `feature_action` | Действие с функцией | `feature`, `action`, необязательный публичный `item_id` |
| `section_view` | Видимость заголовка раздела | `section` |
| `telegram_click` | Предусмотренная Telegram-ссылка | `destination`, `placement` |
| `outbound_click` | GitHub или email | `destination`, `placement` |
| `advertising_stage` | Доступный этап рекламной загрузки | `placement`, `stage` |
| `media_error` | Ошибка изображения, модели или видеообложки | `media` |
| `web_vital` | Результат измерения документа | `metric_name`, `metric_value`, `rating` |

`feature` различает `menu`, `scene`, `cover`, `mosaic`, `carousel`, `story`, `faq`, `background`, `theme`, `language`. Движения указателя, кадры анимации и автоматическая смена обоев 3D не порождают событий действий.

`error_code` содержит только `validation`, `captcha`, `rate_limited`, `unauthorized`, `unavailable` или `request_failed`. Значение внешней ошибки не копируется в параметры.

Для рекламы `request` означает запрос к загрузчику, а `container_ready` означает наличие контейнера iframe. Ни один из них не подтверждает заполнение, оплаченный показ или доход. VAST включается только явным `PUBLIC_HILLTOP_VAST_ENABLED=true`; в выпуске аналитики он выключен.

Web Vitals относятся к загруженному документу, а не к каждой смене обоев Astro. LCP и INP передаются в миллисекундах; CLS безразмерен. Разные `metric_name` нельзя усреднять вместе. Полевая статистика появится по мере поступления реального трафика.

## Настройка GA4 владельцем

Настройте существующий ресурс до production-проверки. Пароли, cookies, токены и ключи в тикет не добавляйте.

1. Откройте GA4 и выберите ресурс сайта. В **Администратор → Потоки данных → Web** сверьте Measurement ID: `G-T8PQT8GE9B`. При несовпадении остановитесь и уточните ресурс; новый Firebase-проект не нужен.
2. В этом потоке выключите **Улучшенную статистику / Enhanced Measurement**. Просмотры, поиск, ссылки и формы отправляются кодом сайта. Автоматические история браузера, поиск и формы могут создавать дубли или передавать свободный ввод. Стандартные события GA4 вроде `session_start` остаются отдельными служебными событиями.
3. В **Настройки данных → Хранение данных** установите 14 месяцев. Не включайте BigQuery, платные подключения или новую Google Ads связь.
4. В **Отображение данных → Пользовательские определения** сначала проверьте существующие определения по имени параметра. Создайте отсутствующие измерения с областью **Событие**: `locale`, `page_type`, `item_id`, `collection_id`, `category`, `variant`, `placement`, `content_type`, `stage`, `action`, `feature`, `destination`, `filter_type`, `filter_id`, `search_terms`, `error_code`, `media`, `metric_name`, `rating`, `direction`, `method`, `section`, `target_page`, `wallpaper`.
5. Создайте отсутствующие пользовательские показатели `result_count`, `query_length`, `position`, `metric_value`, `card_impressions`, `card_selections`, `wallpaper_views`, `download_starts`, `telegram_transitions` с областью **Событие**, единица **Стандартная**. Для `metric_value` единица зависит от `metric_name`, как описано выше.
6. В **Ключевые события / Key events** добавьте `wallpaper_download` и `telegram_click`. Счётчик: **Один раз на событие**. Повторные осмысленные скачивания учитываются; для конверсии пользователей используйте число пользователей с событием.
7. В **Пользовательские определения → Вычисляемые показатели** создайте `card_ctr`: формула `{card_selections} / {card_impressions}`, единица **Процент**. Создайте `downloads_per_view`: `{download_starts} / {wallpaper_views}`, единица **Стандартная**. В редакторе выберите соответствующие метрики из подсказок. Второе значение означает число запусков на просмотр, а не процент уникальных пользователей. Бесплатный стандартный ресурс допускает пять вычисляемых показателей; используем два. [Документация Google](https://support.google.com/analytics/answer/14166471?hl=en).
8. Настройки сохраните. Новые определения и обычные отчёты могут появляться с задержкой; наличие событий сначала проверяется в DebugView.

### Исследование «Основная воронка»

В **Исследования → Исследование воронки** создайте открытую воронку. Шаги: `page_view`, `card_view` с `content_type=wallpaper`, `wallpaper_view`, `download_click`, `wallpaper_download`. Между шагами допускаются другие события. Прямые входы на работу сохраняются благодаря открытой воронке; их нельзя считать потерями на карточках.

Добавьте разрезы по `locale`, `collection_id`, источнику/каналу сеанса и категории устройства. Для сравнения desktop/mobile используйте отдельную вкладку скачиваний с `variant`; у просмотра работы этот параметр отсутствует. Не применяйте фильтр варианта ко всей воронке. Сравнивайте посетителей работы со скачиванием и число запусков PNG отдельно. Telegram-переходы показывайте отдельной целью; смешанный общий процент ключевых событий не заменяет конверсию скачивания.

### Исследование «Эффективность коллекций»

Создайте исследование свободной формы. Строки: `collection_id`, затем `item_id`. Значения: `card_impressions`, `card_selections`, `card_ctr`, `wallpaper_views`, `download_starts`, `downloads_per_view`, `telegram_transitions`. Счётчик каждого действия передаётся как 1 только на соответствующем событии. Общие фильтры и разрезы: `locale`, источник сеанса и устройство. Для `downloads_per_view` используйте только параметры, общие у просмотра работы и запуска PNG: `collection_id`, `item_id`, `locale`, источник сеанса и устройство. Создайте вкладки с фильтром по событию для `card_view`, `content_select`, `wallpaper_view`, `wallpaper_download` и `telegram_click`; показывайте число событий и пользователей.

CTR карточек рассчитывается как `content_select / card_view` при одинаковых коллекции, типе карточки и размещении. Конверсия работы рассчитывается по пользователям с `wallpaper_download` относительно пользователей с `wallpaper_view`. Telegram без контекста работы, например на contact, относится к отдельному итогу сайта, а не к выдуманной коллекции. Вычисляемые показатели используют отдельные счётчики, поэтому не требуют формулы с условной фильтрацией имён событий. Для CTR оставьте отдельную вкладку `content_type=wallpaper` с разрезом `placement`. На вкладке `wallpaper_download` сравнивайте `download_starts` по `variant`. Фильтры `variant`, `placement` и `content_type` не применяются к `downloads_per_view`: соответствующих параметров нет у его знаменателя или у обоих событий. Конверсию уникальных пользователей проверяйте в воронке, отдельно от числа запусков на просмотр.

## Production-приёмка

После подтверждённого deployment запишите версию и откройте сайт в своём браузере. Разрешите аналитику. Для DebugView выполните в консоли только своего браузера:

```js
localStorage.setItem('want-analytics-debug', 'true');
location.reload();
```

В **Администратор → DebugView** проверьте события и параметры. Сравните один переход Astro с одним `page_view`; переключение desktop/mobile даёт `variant_change`, сохраняя число просмотров. Проверьте видимость карточек, поиск с нулевой выдачей и распознанными терминами, PNG обоих вариантов, оценку, комментарий, обратную связь и Telegram. По рекламным объявлениям не кликайте.

Отзовите аналитику в этой и другой вкладке: новые продуктовые события прекращаются, просмотр и PNG остаются доступны. В параметрах не должно быть текста запроса, формы, email, сырых ошибок, query или fragment. Удостовериться в отсутствии события сразу после отказа можно также по запросам браузера; отсутствие строки в обычном отчёте само по себе этого не доказывает.

После проверки удалите диагностический выбор и перезагрузите страницу:

```js
localStorage.removeItem('want-analytics-debug');
location.reload();
```

Подтвердите в тикете версию, настройки GA4, наличие двух исследований и результат проверки. Тикет остаётся открытым до этого подтверждения. DebugView, локальные тесты и факт deployment считаются разными видами проверки.

## Проверки разработки

`make test-frontend` включает контракты параметров и гонки согласия. `bun run test:analytics-ui` запускает отдельный Chromium с подменёнными Firebase, GA4, рекламой и API. Эти проверки не отправляют контрольный трафик в production GA4 и не доказывают получение реальных событий Google.
