[Успешная публикация этой revision](https://github.com/andrey-krasheninnikov/want-wallpapers/actions/runs/37261767064) подтверждает multi-platform digest `sha256:89e0fa95a6df6ae1006888b69d2bea2f64e316e95d77a485db2fbfa3361b1a38`. Это доказательство публикации образа; его совпадение с текущим origin требует отдельного readback сервера.

Свежие обезличенные HTTP-результаты находятся в [2026-10-05-http.json](2026-10-05-http.json). Запросы к публичному Cloudflare endpoint с `User-Agent: SiteAuditBot` возвращают 200 для robots, sitemap, `/ru/`, admin login и публичного API каталога. Последние два ответа имеют `Cache-Control: no-store` и `CF-Cache-Status: DYNAMIC`. Это не подтверждает доступ настоящего краулера Semrush с его IP и настройками кампании.

Origin-файл robots.txt сохраняется. Добавление и объединение managed robots описано в [документации Cloudflare](https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/). Внешнюю директиву `Content-Signal: search=yes,ai-train=no,use=reference` должен проверить владелец Cloudflare при production-проверке.

## Реализация и договорённые ограничения

- Поиск во всех четырёх локалях получает `noindex, follow`, исключается из sitemap и не содержит hreflang. Параметры `q`, `category`, `collection` и существующая фильтрация сохраняются. Ошибки также не имеют hreflang. Индексируемые страницы имеют один canonical, взаимные `en`, `ru`, `zh-CN`, `pt-BR` и английский `x-default`.
- SSR-фрагменты с email защищены настоящими комментариями `email_off`, сохранение которых проверяется после сборки. Прямой `mailto:` работает без JavaScript. [Механизм Cloudflare](https://developers.cloudflare.com/waf/tools/scrape-shield/email-address-obfuscation/).
- Скачивание PNG использует нативные GET-формы. Сохранены адреса, filenames, desktop/mobile и событие `want:download`. Оригинал открывается в `<details>` через исходный PNG `<img>`. CSP разрешает формы того же origin.
- Редакционные тексты в `frontend/src/data/editorial.ts` хранятся отдельно от перезаписываемого snapshot каталога. Они описывают существующие изображения, реальные размеры оригиналов, формат, ориентации, установку и действующую лицензию. Длинные тексты расположены ниже изображения; китайский текст сегментируется через `Intl.Segmenter`.
- Повторяемые классы Button, Badge, Card и карточек галереи вынесены в существующий stylesheet. Сохраняются semantic tokens, варианты, состояния и доступность.
- Тематические ссылки из коллекций дают `/search/?q=city` минимум два разных контекстных источника.
- Статический `/llms.txt` формируется из каталога при сборке: описание, публичные разделы четырёх локалей, коллекции, обои и действующая лицензия. Административные адреса, API и пользовательские данные исключены. [Формат](https://llmstxt.org/).

Backend API и схема БД не изменяются.

## Проверки

HTML разбирается Bun HTMLRewriter, XML — strict SAX с явно объявленной зависимостью. Весь результат сборки проверяется на внутренние адреса и фрагменты, canonical, взаимность hreflang, sitemap, noindex, robots, llms, CSP и отсутствие PNG в обычных навигационных ссылках. Отрицательные тесты проверяют сломанные адреса, конфликтующие альтернативы и некорректный XML.

Браузерные проверки охватывают четыре локали и ширины 320, 768, 1024, 1440; оба скачивания, filenames и байты; отказ от необязательных cookies и ошибку региона; просмотр оригинала, клавиатуру, фокус, axe; поиск, обратную навигацию и пустые результаты. Реальные скачивания проверяются в контексте с отключённым JavaScript. Для axe используется копия того же DOM с удалёнными скриптами сайта, поскольку таймеры axe не работают в таком контексте.

Локальная оценка 192 индексируемых страниц: HTML уменьшился с 8 019 631 до 7 181 470 байт (10,5%). До изменений 185 страниц имели долю текста не выше 10%, после — 0. Ни одна индексируемая страница не имеет меньше 200 слов по локальной сегментации. Подсчёт включает видимый текст страницы, а не только редакционное дополнение. Это локальная оценка, не методика или подтверждение Semrush; [ориентир Semrush](https://www.semrush.com/kb/542-site-audit-issues-list) проверяется повторным production-аудитом после отдельного релиза.

Локально прошли `make check`, `make test` и полный `make test-ui` (63 теста). Обязательные команды: `make check`, `make test`, `make test-ui`; перед merge должны пройти актуальные CI `verify`, `Runtime (amd64)` и `Runtime (arm64)`. После реализации выполняются отдельные Standards и Spec ревью относительно закреплённого основания. PR использует `Refs #17, #18, #23, #24, #25`, squash merge в `development` — с проверкой source SHA через `--match-head-commit`, без обхода защиты. Feature-ветка сохраняется.

## Отложенная production-проверка

1. Сверить deployed revision и image digest с сохранённым origin-выводом.
2. Проверить effective robots и managed Cloudflare directive, сохранив sitemap и ограничения `/admin/`, `/api/`.
3. Подтвердить HTTPS-доступ настоящего Semrush crawler, его scope, исключения и поведение кеша приватных страниц.
4. После отдельного production-релиза проверить email opt-out, PNG, `/llms.txt`, язык, индексацию и sitemap через Cloudflare.
5. Запустить отдельный новый аудит с сопоставимыми настройками и сравнить все десять категорий и затронутые URL. Только после этого решать закрытие тикетов.
